レビューを出す前に、1回だけ通す

Claude Code の /code-review を紹介する3〜5分のLT。この仕様書のとおりに Keynote で13枚作ると、撮影済みのキャプチャ12枚がすべて収まります。

スライド 13枚 キャプチャ 12枚 所要 4分45秒 聞き手 エンジニア中心

作りはじめる前に：STEP5_1 はトリミングしてください

この画面の上部に /model（Sonnet 5）と /effort medium の実行履歴が写り込んでいます。これは Claude Code 全体の設定で、/code-review high の「厳しさ」とは別の機能です。

そのまま出すと「さっき設定した effort と同じもの？」という質問が出ます。コマンド候補が出ている下半分だけを切り出して使ってください。

スライドに出す文字

「README のルールに違反している」
粗利 = 売上 − 原価 利益分配は原価ではなく、粗利から払う

貼る画像（2枚を上下に）

STEP7_2_:code-review実行結果_サブエージェント_high.png 配置：該当の指摘だけを切り出して、大きく。このLTで唯一、文字を読ませる画像
STEP7_3_:code-review実行結果2_サブエージェント_high.png 配置：下に小さく、または総括の一文だけを切り出して添える

話すこと

このリポジトリの README には、会計上の決めごとが書いてあります。「粗利は売上マイナス原価」「利益分配は原価ではなく、粗利の中から払う」。

【ここで一拍おく】

コードではなく、README です。

実装はこれを守っておらず、分配を原価として引いていました。Claude はその README を読んだ上で、「この2つは README に書かれたルールへの違反だ」と指摘してきました。

文法チェックでも、よくあるバグパターンの検出でもないですよね。リポジトリの中の決めごとを読んで、それと突き合わせている。ここまでやるとは思っていませんでした。

この画像を出す理由

LTの結論そのもの。ここだけは投影して、会場の一番うしろから文字が読めるか必ず確認してください。読めないなら、指摘部分を切り出して拡大するか、テキストで打ち直します。

12

使い方

22秒

スライドに出す文字

  • /code-review — 引数なしでOK
  • /code-review high — 厳しさ low〜max
  • /code-review --fix — その場で直す
  • /code-review --comment — PRに行コメント

貼る画像

画像なし（文字だけ・4行）

話すこと

使い方です。基本は引数なしでいいです。物足りなければ high や max。今回は medium から high で3件増えました。--fix を付けると指摘するだけでなくその場で直します。--comment を付けると GitHub のPRに行ごとのコメントとして投稿してくれます。

ちなみに今回は8件出ましたが、毎回この精度が出るとは限りません。差分は自分でも見ます。

最後の一言を入れる理由

質疑でほぼ確実に聞かれます。先に自分から言っておくと、誠実に見えるうえに質疑が短くなります。

4分に収めたいとき — 削る順番

  1. 09（厳しさを上げる）を10に統合 → −10秒。10のスライドに /code-review high と併記すれば足ります

06 と 11 は削らない
